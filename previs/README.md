# Previs in Unreal Engine

This folder holds everything Claude Code needs to block, light and render the site's six previs
shots in your own copy of Unreal Engine. Unreal cannot run on GitHub Pages or in the cloud session
that built this site, so this part happens on your computer. Until it does, the site's
**Virtual production / Previs** section shows a plan view of each shot with a "PREVIS PENDING"
tag. Once you render, it plays your Unreal clips instead.

| File | What it is |
|---|---|
| `shotlist.json` | The shots: Super 35 camera, lens, stop, focus, keyframes, lighting and the stage. **Generated; don't edit it by hand.** |
| `bust.md` | The grey-box bust, built from the same numbers as the plaster bust in the Light study. |
| `../prompts/previs-unreal.md` | All the steps below as one long prompt, if you prefer to paste it in one go. |

`shotlist.json` is generated by `npm run previs:shotlist` from two sources:

- `assets/js/core/presets.js`, the lighting table the Light study also uses;
- `assets/js/core/optics.js`, the depth-of-field maths the Focus study also uses.

So the previs, the Light study and the Focus study always agree. If you change a preset, regenerate
the file. `npm run check` fails when it is out of date.

## The six shots

Each shot is a Motion Prompt camera move, rebuilt in Unreal units.

| Shot | Move | Lens | What happens | Lighting |
|---|---|---|---|---|
| PV-010 | #027 Dolly in | 24 mm T2.8 | Push 5.8 m toward the head (8 → 2.2 m); focus follows. | Rembrandt #101 |
| PV-020 | #033 Rack focus | 24 mm T1.4 | Locked off; focus pulls from a practical at 2 m to the head at 9 m. | Low-key #114 |
| PV-030 | #030 Orbit | 24 mm T2.8 | 109° arc at 6 m. **The camera is parented to a pivot at the head, and the pivot's yaw is keyed.** | Split #100 |
| PV-040 | #032 Dolly zoom | 9.6 → 24 mm T4 | Pull back 3.2 → 8 m while zooming, with f = 24·d/8, so the head keeps its size. | Butterfly #102 |
| PV-050 | #031 Crane up | 24 mm T2.8 | Rise 1.4 → 9 m, tilting down to −44°. Keys baked every 3 frames. | Backlight #097 |
| PV-060 | #043 Whip pan | 24 mm T2.8 | Camera A whips 26° right, cuts to camera B (profile) on frame 50, B settles. | Rim #098 |

All six shots share these settings:

- 2048 × 858 at 24 fps, Super 35 filmback (24.89 × 18.66 mm) cropped to 2.39:1, circle of confusion 0.025 mm.
- Unreal axes: X forward, Y right, Z up, centimetres. The subject sits at the origin and faces −X, with the head centre at (0, 0, 150).

## Before you start

You only need to do these once.

1. **Install Unreal Engine** and open (or create) the project you want to use for previs.
2. **Enable two plugins** in that project: **ModelContextProtocol** (the server) and
   **AllToolsets** (the tools). Restart the editor.
3. **Start the MCP server.** In the editor console (the `~` key), run:
   ```
   ModelContextProtocol.StartServer
   ModelContextProtocol.GenerateClientConfig ClaudeCode
   ```
   The second command writes the `.mcp.json` that Claude Code reads. It goes next to your
   `.uproject` (on a source build, at the workspace root).
4. **Install the Unreal plugin for Claude Code.** Open Claude Code and run:
   ```
   /plugin install unreal-engine-skills-for-claude-code@claude-plugins-official
   ```
   If Claude Code says the marketplace is unknown, add it first with
   `/plugin marketplace add anthropics/claude-plugins-official`, then run the install again.
5. **Enable it for the Unreal project too.** Add this to `.claude/settings.json` in the
   **Unreal project folder**. Create the file if it doesn't exist.
   ```json
   {
     "enabledPlugins": {
       "unreal-engine-skills-for-claude-code@claude-plugins-official": true
     }
   }
   ```
   This website repo already enables it in its own `.claude/settings.json`.
6. **Save and commit the Unreal project** before every session. Claude edits the live editor, and
   not every change can be undone.
7. **Start Claude Code from the folder that holds `.mcp.json`** (the Unreal project folder; on a
   source build, the workspace root). Use `--add-dir`
   to give it this repo, so it can read the shot list and write renders into it:
   ```
   cd /path/to/YourUnrealProject
   claude --add-dir /path/to/Karan-Chaudhary
   ```
   Run `/mcp` and check that `unreal-mcp` is connected.

> **Safety.** Don't run this session with `--dangerously-skip-permissions`. The Unreal plugin can
> run arbitrary Python inside the editor, through `execute_tool_script`. The prompts below only ask
> for it in step 4, and only after you say OK; steps 0–3 each open with a line forbidding it without
> your OK (the plugin otherwise likes to batch tool calls into Python).

In every prompt below, replace `<repo>` with the absolute path to this repo, for example
`/Users/you/code/Karan-Chaudhary`. Paste the prompts one at a time, and check each result before
moving on.

## Step 0 · Discover (read-only)

Nothing changes in this step. It finds the exact tool names on your engine version, which vary
between releases.

```text
Never call execute_tool_script or run Python without first showing me the full script and waiting
for my explicit OK.
Use the unreal-mcp skill. First verify the connection with one read-only call (list the actors in
the current level). Then list_toolsets, and describe_toolset for the Sequencer, actor/level,
lighting, editor/screenshot and programmatic toolsets. Change nothing.
Report the exact toolset and tool names for:
  - creating a Level Sequence and subsequences, and setting the display rate;
  - spawning a CineCameraActor and setting Filmback, Crop, CurrentFocalLength, CurrentAperture,
    DiaphragmBladeCount and FocusSettings (Manual, ManualFocusDistance);
  - adding transform, focal-length and focus keyframes, and setting key interpolation and tangents;
  - attaching one actor to another (camera parented to a pivot);
  - adding a camera-cut track;
  - spawning RectLights and PointLights and setting temperature, intensity and source size;
  - Outliner folders, saving assets, and taking a viewport screenshot;
  - Movie Render Queue.
If there is no Movie Render Queue tool, say so plainly. Also call AgentSkillToolset.ListSkills
and tell me whether this project registers any skills that apply.
```

## Step 1 · Stage

```text
Never call execute_tool_script or run Python without first showing me the full script and waiting
for my explicit OK.
Save all first. Create the level /Game/Previs/Maps/PV_Stage and open it.
Read <repo>/previs/shotlist.json (the "stage" and "subject" blocks) and <repo>/previs/bust.md.
Units are centimetres; Unreal axes; the subject is at the origin facing -X, head centre (0,0,150).
Build:
  1. the 18 % grey floor and the curved cyc wall from stage.floor and stage.cyc (flat panels are
     fine);
  2. the grey-box bust from bust.md, starting with the 8-primitive lighting maquette (the rows
     marked ●), on the pedestal from stage.pedestal, with a material M_Plaster
     (base 0.8 linear, roughness 0.9, specular 0.3);
  3. the 12 grey columns of stage.colonnade at the listed bases;
  4. the props in stage.props (post, rock, and the practical with its 2700 K PointLight);
  5. bust.md's flat backdrop card at X = 160 cm, in its own folder Previs/Stage/LookdevCard and
     hidden. It is only for step 2's comparison stills; the moving shots need the colonnade and the
     cyc visible behind the head.
Put everything else in the Outliner folder Previs/Stage. Save, then show me a viewport screenshot from
(-300, 0, 150) looking at the head, and one wide from (-1200, -600, 400).
Stop there and wait for me.
```

When it reports back, look at the screenshots. The nose, brow and chin should read clearly in
silhouette before you light anything.

## Step 2 · Lighting

```text
Never call execute_tool_script or run Python without first showing me the full script and waiting
for my explicit OK.
Read the "lighting" block of <repo>/previs/shotlist.json. For every preset, create its lights
exactly as listed: RectLight at "loc" with rotation "rot" (already aimed at the head),
SourceWidth/SourceHeight from sourceWidth/sourceHeight, bUseTemperature = true,
Temperature = kelvin. Intensities are relative: key = 1, fill = 1/(ratio - 1).
The formulas, if you need to check: X = -d·cos(el)·cos(az), Y = -d·cos(el)·sin(az),
Z = 150 + d·sin(el), d in cm, az positive = camera-left.
Pick one base intensity for a key of 1 so that, with camera exposure on Manual, the lit cheek of
the Rembrandt preset sits around 70 %, and use that same base for every preset. Scale the cyc's
light by 2^backgroundStops. Put each preset in Outliner folder Previs/Lights/<preset> and turn every
preset off except rembrandt. Show the LookdevCard for these stills only. Save, then screenshot the
bust from (-200, 0, 150) under rembrandt, butterfly and split, switching presets in turn. Hide the
LookdevCard again afterwards.
```

The Rembrandt screenshot should show a small triangle of light on the shadow-side cheek. The
butterfly one should show a shadow directly under the nose. If neither does, ask Claude to check
the key's elevation and the bust's nose before going on.

## Step 3 · Sequence

```text
Never call execute_tool_script or run Python without first showing me the full script and waiting
for my explicit OK.
Read the "shots", "filmback", "camera" and "sequence" blocks of <repo>/previs/shotlist.json.
Create the master Level Sequence /Game/Previs/Seq/PV_Master at 24 fps. For each shot:
  1. Create the subsequence named in shot.sequence (24 fps, shot.frames long) and place it in the
     master at shot.masterStartFrame.
  2. Add a spawnable CineCameraActor named shot.camera. Filmback preset "Super 35mm"
     (24.89 x 18.66), crop 2.39:1, CurrentFocalLength = lens.focal, CurrentAperture = lens.tStop,
     DiaphragmBladeCount = lens.blades, Focus Method Manual, ManualFocusDistance = lens.focus (cm),
     White Balance Temp = the preset's cameraWB, Motion Blur Amount from shot.motionBlur.
  3. Key every entry in shot.keys at its time "t" (keys may sit between frames): location "loc",
     rotation "rot", CurrentFocalLength "focal", ManualFocusDistance "focus". Apply shot.ease
     ("unreal" says how: flat weighted tangents for cubic in-out; Auto tangents for baked keys).
     Values hold before the first key and after the last.
  4. PV-030: do not key the camera. Spawn the pivot named in shot.rig at rig.loc, attach the camera
     to it at rig.offset with rig.cameraLocalRot, and key only the pivot's Yaw from keys[].pivotYaw.
     This makes the move a true arc; two transform keys on the camera would cut a straight chord.
  5. PV-040: key focal and location with identical times and easing, so focal/distance stays at
     3 mm per metre (shot.constraint).
  6. PV-060: add the second camera from shot.cameraB with its own keys, and a camera-cut track that
     follows shot.cuts (camera A from frame 0, camera B from frame 50).
  7. Turn on only the lights of shot.lighting inside this subsequence; set the others to 0.
Add a camera-cut track to the master that plays the shots back to back. Save, then show me three
stills per shot (first frame, middle frame, last frame) through the shot camera.
```

Check the stills against the plans in the site's Previs section. The camera paths, lenses and
lights should match.

## Step 4 · Render

```text
Render every shot with Movie Render Queue: PNG, 2048 x 858, anti-aliasing override with 1 spatial
and 8 temporal samples (PV-060: 9 temporal samples and a 360° shutter, from its motionBlur
block), the output folder <repo>/media/previs/<shot id>/ and the file name {frame_number} padded to
4 digits. One job per shot, using its subsequence.
If there is no Movie Render Queue tool, do NOT run anything yet: show me the Python you would pass
to execute_tool_script (unreal.MoviePipelineQueueSubsystem and friends), explain what it does, and
wait for my explicit OK before running it.
```

The PNG folders under `media/previs/<shot>/` are git-ignored and never deployed.

## Step 5 · Encode and publish

Back in this repo, in a normal terminal:

```sh
npm run previs:encode
```

For each `media/previs/<id>/` folder, this writes two files:

- `media/previs/<id>.mp4`: H.264, 1920 wide, BT.709, faststart, about 4 MB at most.
- `media/previs/<id>.jpg`: a poster taken at 40 % of the shot.

It then prints a `media: { … }` block. Paste that block over `previs.media` in
`data/portfolio.js`, then run:

```sh
npm run check
```

Commit the `.mp4` and `.jpg` files and `data/portfolio.js`. After the push, the Previs section
plays your Unreal renders in place of the plans.

## Changing the shots

The shots are defined in `tools/previs-shotlist.mjs`, and the lighting in
`assets/js/core/presets.js`. To change them:

1. Edit one of those files.
2. Run `npm run previs:shotlist`, then `npm run check`.
3. In Unreal, ask Claude to update only the shots that changed.
